## 1. Паспорт проекта

- **Название проекта:** `CVD Multi-Label Risk Calculator — Система мультилейбловой классификации риска сердечно-сосудистых заболеваний`
- **ФИО:** `Николаева Алина Алексеевна`
- **Группа:** `ИНБО-20-24`
- **Контакт:** `@allliin`

- **Краткое описание (2-4 предложения):**  
 >Проект посвящён разработке REST API-сервиса для мультилейбловой классификации риска пяти сердечно-сосудистых заболеваний: ишемическая болезнь сердца, гипертоническая болезнь, сердечная недостаточность, перикардиальные заболевания и опухоли сердца.
 >Используются данные мониторинга пациентов (возраст, пол, давление, холестерин, глюкоза, образ жизни), предобработка признаков и ансамблевые модели (Random Forest) с оценкой по метрикам F1-micro, F1-macro, Accuracy и Hamming Loss.
 >Результат — масштабируемый FastAPI-сервис с эндпоинтами /predict и /health, возвращающий вероятности заболеваний и интерпретируемые уровни риска («Низкий»/«Средний»/«Высокий»).

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

Если структура проекта отличается от базовой, опишите это здесь.

## 3. Требования и установка

### 3.1. Требования

- Python >= 3.10
- pip (менеджер пакетов)
- (Опционально) virtualenv или venv для изоляции окружения

### 3.2. Установка окружения

Примерный сценарий (можно адаптировать под ваш проект):

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

Если у проекта есть какие-то особенности установки (дополнительные шаги, внешние сервисы и т.п.), опишите их здесь.

## 4. Как запустить проект

### 4.1. Запуск обучения модели
Обучение выполняется в Jupyter Notebook
```bash
cd project
source .venv/bin/activate  # при необходимости
jupyter notebook notebooks/eda_and_experiment.ipynb
```

### 4.2. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
source .venv/bin/activate      # при необходимости
python -m src.service.main        
```

- Сервис поднимется на http://0.0.0.0:8000 (порт настраивается в configs/.env)
- Доступные эндпоинты: 
GET/ Корневой эндпоинт с информацией о сервисе
GET/docs Swagger UI для интерактивного тестирования API
GET/api/v1/health Проверка статуса сервиса и загрузки модели
POST/api/v1/predict Мультилейбловое предсказание риска 5 заболеваний
- Для проверки используйте 
curl -X POST "http://localhost:8000/api/v1/predict" \
  -H "Content-Type: application/json" \
  -d '{
    "age": 55,
    "gender": 2,
    "height": 170,
    "weight": 75,
    "ap_hi": 145,
    "ap_lo": 90,
    "cholesterol": 2,
    "gluc": 2,
    "smoke": 1,
    "alco": 0,
    "active": 1
  }'
